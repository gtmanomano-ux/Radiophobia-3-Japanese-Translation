# Radiophobia 3 会話グラフ翻訳方針

## 目的と基本方式

会話を文字列 ID の順番だけで訳さず、会話グラフから発話順、選択肢、返答、分岐条件、話者を確認して、日本語の台詞として書き直す。原文の意味・感情・意図を保ちつつ、人物の関係と場面に合う自然な口語を目指す。

Tyranny の `会話グラフ翻訳方針ver2.md` にある「グラフを文脈の基準にする」「イベント単位で執筆する」「翻訳結果を原本と照合してから適用する」という方式を採用する。ただし、Tyranny 固有の Entry ID、章構成、JSON、`jp` / `jpr` の書き戻し手順は持ち込まない。

## Radiophobia 3 の入力と出力

- 会話構造：`F:\Games\Radiophobia 3\gamedata\config\gameplay\dialogs*.xml` など。`<dialog id>`、`<phrase id>`、`<text>`、`<next>`、`<precondition>`、`<action>` などを読む。会話構造の多くは `gamedata.sq_*` アーカイブ内にあるため、ルーズファイルだけで全体を判断しない。
- 表示文：`F:\Games\Radiophobia 3\gamedata\config\text\jpn\` 内の `<string id="…"><text>…</text></string>`。会話以外の文も混在する。
- 原文：同じ ID の英語テキストをゲーム本体のアーカイブ、または来歴を確認した英語データから取得する。既存の日本語や機械翻訳された文を英語原文の代わりにしない。
- 読み込み範囲：`gamedata\config\localization.ltx` の `files` を確認し、ゲームで使われる文字列テーブルを特定する。ファイル名が似ていても、一覧にないファイルを有効と決めつけない。
- 最終出力：ゲームが実際に読む `text\jpn` の XML の表示文。翻訳途中の原文、グラフ、作業結果は `Translate` 側で管理し、適用時までゲーム本体を変更しない。

現時点では Radiophobia 3 用の完成済み `graph_index.json` や翻訳パケットは存在しない。本書は、その作成と翻訳に使う方針であり、作成済み・翻訳済みという進捗を意味しない。

## 会話グラフの作成

1. ゲーム本体のアーカイブとルーズファイルを確認し、実際に読み込まれる `gameplay` と文字列テーブルの対応を確定する。アーカイブ内のファイルにルーズファイルが重なる場合は、実際の優先順位を確認する。
2. `dialog id` と `phrase id` を組にして節点を識別する。`<next>` の全リンク、分岐条件、情報フラグ、スクリプトの `precondition` / `action` を記録する。数値 ID の大小を発話順とみなさない。
3. `<phrase><text>` が文字列 ID を指す場合は、参照先ファイル、英語原文、現行日本語を結び付ける。直接表示文が入る場合はその違いを記録する。
4. 話者は、会話の開始条件、キャラクター設定、前後の節点、ゲーム内表示から特定する。ID の命名だけで確定しない。不明なものは不明として残す。
5. 同じ文字列 ID が複数の会話から参照される場合は共有文として扱い、訳を一つにする。異なる文脈で訳し分けが必要なら、ゲーム側での参照関係を確認してから扱いを決める。
6. 参照先のない ID、文字列のない節点、重複 ID、到達しない節点、スクリプトでのみ生成される発話を検出し、翻訳対象と要調査対象を分ける。重複 ID を自動的に統合しない。
7. 原本のパス、サイズ、SHA-256、抽出元アーカイブを記録する。原本の構造が更新されたときだけグラフを再作成し、翻訳中にグラフを恣意的に変更しない。

グラフの各節点には、少なくとも会話 ID、節点 ID、参照文字列 ID、英語原文、現行日本語、前後リンク、条件、行動、話者、参照元ファイルを保持する。

## 翻訳範囲と作業単位

1. 会話グラフに参照される表示文を主対象とする。プレイヤー選択肢、NPC の返答、汎用会話、商人・修理・案内・イベント会話を含める。
2. クエスト文、人物説明、アイテム、UI など会話外のテキストは別領域として管理する。ただし、会話を理解するために必要な名称や設定は参照する。
3. 一つの会話と、その選択肢から直接の返答、分岐後の合流までを同じ作業単位にする。長い会話を分割するときも、担当範囲に会話全体の英文とグラフを添える。
4. 場所、時点、会話目的、登場人物が変わる地点でイベントを区切る。共有文の担当を一つに固定し、複数の結果で同じ ID を上書きしない。
5. 作業パケットには、担当文字列 ID、原文、現行訳、会話経路、前後の発話、話者、条件、関連用語を載せる。規模は文脈を保って推敲できる量にし、Tyranny の「最大80 Entry」を機械的に当てはめない。

## 台詞の執筆

会話文への指示
これは翻訳ではなく、日本語版ゲームの台詞執筆として扱う。
原文の意味・感情・意図を保ちつつ、日本人脚本家が最初から日本語で書いたような自然な会話文に修正
する。
- 実際の会話で使う口語表現を優先する。
- 直訳調や不自然に硬い表現を避ける。
- 不要な主語・代名詞・接続詞は省略する。
- 語順変更、意訳、文の分割・結合を積極的に許可する。
- 前後の文脈とキャラクターの口調を考慮する。
- 台詞中の用語・固有名詞は、訳語や表記を決める前に必ず `glossaly` を参照する。
- 既存訳が不自然なら、原文の意味を保ったうえで台詞全体を書き直してよい。
最終基準は「翻訳として正しいか」ではなく、「日本語で制作されたゲームの台詞として違和感がないか
」とする。

説明文への指示
説明文は、プレイヤーが状況や対象を正しく理解し、判断に使える日本語で書く。
- 説明文に出る用語・固有名詞は、訳語や表記を決める前に必ず `glossaly` を参照する。
- クエストの目的、達成条件、場所、人物、報酬、危険、時間の前後関係を原文どおりに伝える。
- 人物・場所・アイテムの説明では、事実と噂、確定情報と推測を混同しない。
- ゲーム世界の雰囲気は残しつつ、直訳で意味が取りにくい文は自然な語順に整える。
- 同じ対象を指す名称は会話文や UI と揃え、別の対象を同じ訳語で紛らわしくしない。
- 見出し、本文、箇条書きの役割を保ち、必要な情報を省略しない。原文にない攻略情報や設定を足さない。

UIへの指示
UI は、画面上で一目で意味と操作結果が分かる日本語にする。
- UI に表示する用語・固有名詞は、訳語や表記を決める前に必ず `glossaly` を参照する。
- ボタン、メニュー、状態表示、通知は短く明確にし、同じ操作や状態には同じ表記を使う。
- 数値、単位、キー名、条件、否定、警告の意味を正確に保つ。選択後に起こる動作を誤解させない。
- 画面幅や表示時間に合わせて簡潔にするが、意味を削って曖昧な略語にしない。
- 会話文・説明文と用語を揃え、UI 特有の短い表現が必要な場合だけ別表記を記録する。
- 改行や空白を表示不具合の対策として追加せず、実機で文字の欠け、折り返し、はみ出しを確認する。

## XML と制御要素の保護

- 変更対象は、採用した日本語文字列テーブルの `<text>` の表示内容だけとする。`string id`、`dialog id`、`phrase id`、リンク、条件、行動、スクリプト名、ファイル名、要素構造は保持する。
- `\n` などの改行指定、書式タグ、変数、書式指定子、XML エンティティを一件ずつ分類し、ゲーム側の意味を確認して保持する。表示文と制御要素を混同しない。
- XML の宣言、実際のエンコーディング、改行、インデントを対象ファイルに合わせる。`encoding="windows-1251"` と記された現行ファイルもあるため、宣言だけを信用せず、実際のバイト列とゲームでの読み込みを確認する。日本語書き込み時は XML 宣言と実データのエンコーディングを一致させる。
- 既存ファイルに重複 `string id` がある場合は、勝手に削除・統合・並べ替えをしない。読み込み側の挙動と参照元を調べ、必要な修正を別途判断する。
- 今回の日本語表示修正で有効化した `use_new_parse_text = false` は表示基盤の設定として維持する。翻訳作業でフォントや設定を不用意に変更しない。

## 翻訳結果の確認と適用

1. 入力パケットと結果の文字列 ID 集合、原文、グラフ参照を照合し、欠落・重複・余分・原文変更を検出する。
2. 日本語の空欄、英語の残存、人物・用語の表記揺れを確認する。固有名詞や意図的な英語は例外として記録する。
3. XML を解析し、ID、要素順、制御要素、変数、改行指定を適用前後で比較する。機械検証に加えて、イベント全体を読み、選択肢と返答、口調、意味を確認する。
4. 適用対象の原本をバックアップしてから、確定した `<text>` のみゲーム側に反映する。適用後は XML の再解析、原文・ID の照合、再適用時の差分 0 件を確認する。
5. ゲームを再起動し、会話の表示、折り返し、英数字、選択肢、改行、長文を実機で確認する。翻訳件数、文章品質、ファイルの技術的整合性、実機表示を別々に報告する。

翻訳完了の報告には、対象数、訳了数、保留数、検証結果、バックアップ先、反映先、ゲーム内確認の状態を明記する。件数が揃っただけで、実機表示まで確認済みとは扱わない。
